  - シナリオA(健全): 永続的に2秒おきhbを書くバックグラウンドworkerに対し、TTL=10秒で1秒間隔10回測定 → OK 10/10
  - シナリオB(空転): flockを掴んだまま sleep 300 する擬似ハングプロセスを起動し、hbは最初の1回だけ書く。hbを15秒寝かせてから TTL=10秒で1秒間隔10回測定 → SUSPECT 10/10

- 観測: シナリオA (healthy, TTL=10s, 10回): すべて 'OK age=0-1s ttl=10s lock=held' / ok=10 wrong=0。シナリオB (stale, hb凍結後15s～24s): すべて 'SUSPECT age=15-24s ttl=10s lock=held' / suspect=10 wrong=0。合計20/20で偽陽性0・偽陰性0。worker正常終了直後は 'OK age=2s ttl=10s lock=free' となり、ロック解放後にhbが古くなると 'IDLE_NO_LOCK' として別状態で検出できることも確認。
- 結論: ハートビートファイル + Idle TTL(hb経過時間) + flock占有の3点をANDで見る方式は、空転(ロック生きてるが進捗なし)と健全動作を機械的に切り分けられた(20/20 一致、偽陽性/偽陰性0)。ゲートファイルやflockだけでは『資源の有無』しか見えないが、hb経過を併用すると『生きてるが止まってる』が検出できる。既存の ops/mtime_watch/registry.csv の思想（成果物の最終更新時刻を監視）を『各watchdogが明示的に書き込むheartbeat』に置き換える延長で、しきい値だけ対象別に調整すれば実装可能。

- 判定: **効果あり**
- 当てはめ先: Xserver VPS(本番Web) + さくらVPS(生成) + ロリポップ(非配信ミラー) + Cloudflare の3拠点構成。nginx FastCGI 7日・LiteSpeed・Cloudflare の3層キャッシュ。既知の地雷『キャッシュ3層のパージ漏れで直したのに直ってない』『Cloudflareに curl が403で弾かれる → --resolve でオリジンIPへ直接』。
- やったこと:
  - /work/lab/tls_audit に origin (nginx風ヘッダ, Xserver-Origin自己署名証明書, port 18443) と cdn (cloudflare風ヘッダ, Cloudflare-Inc自己署名証明書, port 18444) の2つのHTTPSモックを立てた
  - snapshot.md L8/L23/L24 を根拠に3層キャッシュ構成を再現 (originだけCONTENT_VERSION=v2、cdnはv1のまま=『直したのに直ってない』を模擬)
  - 計画書通りの audit.sh を書き、HEAD/証明書/ネゴ版/暗号/body sha256 を層ごとに取得して diff -u で突合
  - curl --resolve でHOSTを固定しつつ各層のip:portに別々に当てる動作を確認
- 観測: layer差分1画面で検出: Server: cloudflare vs nginx/1.18.0, Cache-Control: public,max-age=3600 vs no-store, CF-Cache-Status: HIT(cdn)/X-Cache: MISS(origin), 証明書subjectも Cloudflare-Inc,Edge vs Xserver-Origin, notAfter 2028-10-13 vs 2027-01-12, 両者TLSv1.3 TLS_AES_256_GCM_SHA384で一致, body sha256が 80e31af...vs c063bcd... と不一致 → キャッシュ由来のstale状態をハッシュ1行で特定
- 結論: 計画の『同じ検査を層ごとに流して1本のdiffで突合』は本当に効く。ヘッダ/証明書/TLSに加えて body sha256 を足すと、キャッシュパージ漏れ(CDN stale)とオリジン未更新を1行で切り分けられる。TLS設定の層間ドリフト(片層だけ古い暗号/旧TLS1.1残存)の早期検知にも乗る、副作用のない読み取り検査。
- 本番に入れるなら: ~/ops/bin/tls_audit.sh として配布、cdn/origin ipを環境変数で渡し、週次cron (例: 0 9 * * 1) で読み取りのみログ。差分はログに残すだけで、パージ/証明書更新/nginx設定変更は人の承認後。戻しは cron 1行削除とスクリプト削除。-k は使わず本番の正証明書で検証、ラボ用の-kはこのスクリプトから外す。
