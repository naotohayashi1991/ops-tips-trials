  - 計画の (d) kill -INT パターンは bash 非対話シェルで `&` バックグラウンド化した子に SIGINT が SIG_IGN として渡る仕様で baseline/handler 共に機能しなかったため、sig_v2.py (SIGINT も登録) と `timeout --preserve-status -s INT 2` に差し替えて再検証。
  - `timeout --preserve-status` 有無の両方を計測し、cron 側の実コマンドで handler の 141 が到達可能かも確認。
- 観測: HANDLER(sig.py): timeout 2 →shell exit=124 / timeout -s TERM 2 →124 / パイプ(SIGPIPE) →exit_python=141 (ただし stderr に 'Exception ignored in sys.unraisablehook ... SystemExit: 141' の残渣あり) / timeout --preserve-status -s TERM 2 →141 ✓ / timeout --preserve-status -s INT 2 →141 ✓. BASELINE(baseline.py): timeout 2 →124 / パイプ →exit=120 + 'BrokenPipeError: [Errno 32] Broken pipe' と 'Exception ignored in: <_io.TextIOWrapper ...>' が stderr に残る / timeout --preserve-status -s TERM 2 →143 (128+15) / timeout --preserve-status -s INT 2 →130. 結論: 『打ち切られた時に Python が常に 141 を返す』はハンドラ追加で達成できるが、現行 cron の素の `timeout N cmd` では timeout 側が 124 を返すため shell 段では 141 を観測できず、ハンドラ単独では意味付けが揃わない。
- 結論: シグナル経由で Python が直接止まる経路(SIGPIPE/非 timeout の SIGTERM/SIGINT)では、ハンドラで常に 141 を返せることを実機で確認した。一方で現行 cron(snapshot.md:171-173)の `timeout N python3 ...` では timeout 自身が 124 を返すので、ハンドラだけでは shell 段の物差しは 124 と 141 に二重化したままで『同じ物差し』にはならない。『141 で揃える』を本気で成立させるなら、ハンドラ追加と同時に該当 cron を `timeout --preserve-status` に切り替える必要がある。
- 本番に入れるなら: (1) refill.py/daily_report.py/longpost.py/philopost.py/resim_all_markets.py の冒頭に SIGTERM/SIGPIPE/SIGINT→sys.exit(141) を追加し、最外 try/except で KeyboardInterrupt/BrokenPipeError も 141 にする。(2) 同時に snapshot.md:171-173 の cron 3行を `timeout --preserve-status -k 120 N` に切替え、wrap_log 配下は wrap_log の中身を見てから判断。(3) scan_health/zombie_watch/postverify/rejectrate の判定ロジックに『141 は打ち切り、124 は未改修 timeout による打ち切り、128+N はシグナル死』の対応表をコメントで明記。(4) SIGPIPE 時の 'Exception ignored in sys.unraisablehook / SystemExit: 141' を監視パターンの除外に登録。戻しはハンドラ登録を削り cron を元に戻すだけ。全て要承認。
