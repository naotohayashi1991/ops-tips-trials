  - nginx CLF を awk で ISO-Z に正規化し、watchdog/factory/nginx の3本を sort -m で合成。全60行のタイムスタンプ単調性を awk で検証。
- 観測: lab 40/40 行が ^[0-9T:-]+Z で始まりマッチ、+0900 / 22:21 の JST 痕跡は0件。親 TZ=Asia/Tokyo の下でも lab は 13:21:29Z (= `date -u` と一致)、未改修は 22:22:09 で9時間ズレ。sort -m 合成60行は strictly non-decreasing (`OK` 判定)。nginx の `[03/Oct/2026:13:21:29 +0000]` と factory の `2026-10-03T13:21:29Z` が同一瞬間として並ぶことを確認。
- 結論: Python 側は logging.Formatter の datefmt+末尾Z+converter=time.gmtime、bash 側は `TZ=UTC date -u +%Y-%m-%dT%H:%M:%SZ` の2点だけで、親プロセスの TZ に関係なく全行が UTC Z 固定になり、nginx の UTC アクセスログと sort -m で素直に時系列合成できた。既存 JST ログに触らなくても『新規は Z固定』という足場があるだけで Cloudflare/nginx との付き合わせが大幅に楽になる。計画書の『成功の基準』は満たした。
